# 시간표 과목·수강 연동 설계

## 목표

에브리타임 스타일로 한 과목의 복수 요일·시간을 시간표에 표시한다. 정규 과목을 시간표에 추가하면 수강 정보(`student_courses`)를 단일 기준으로 저장해 로드맵 과목 선택과 교수 공지 수신 권한에 즉시 반영한다. 수동 커스텀 과목은 시간표 전용으로 관리한다.

## 범위와 원칙

- 정규 과목 시간의 우선순위는 `course_schedules`(강의계획서 파싱 결과), `professor_teaching_slots`(교수 강의 슬롯), 사용자 입력 순서다.
- `student_courses`는 학생과 정규 과목의 수강 관계를 한 행으로 보존한다. 요일별로 수강 관계 행을 중복 생성하지 않는다.
- 실제 수업 시간은 복수 행의 슬롯 테이블에 저장한다.
- 수동 커스텀 과목은 정규 과목·교수·공지와 연결하지 않는다. 시간표에서만 표시한다.
- 새 UI는 테두리 위주의 표현을 피하고 파스텔 카드, 둥근 모서리와 `shadow-sm`을 사용한다. 시간표 격자의 최소 구분선은 기능상 필요한 수준으로만 유지한다.

## 데이터 모델

### 정규 과목 수강과 시간 슬롯

기존 `student_courses`를 수강·권한의 기준으로 유지한다. 새 `student_course_schedule_slots` 테이블은 다음을 가진다.

- `id`: UUID 기본 키
- `student_course_id`: `student_courses.id` 외래 키, `ON DELETE CASCADE`
- `day_of_week`: 한국어 요일(`월`~`금`)
- `start_time`, `end_time`: `time`, 시작이 종료보다 앞서야 함
- `classroom`: 선택값
- `schedule_source`: `syllabus`, `professor`, `manual`, `legacy` 중 하나
- `created_at`, `updated_at`

고유 제약은 `(student_course_id, day_of_week, start_time, end_time)`으로 둔다. 학생별 시간표 조회에 사용하는 `student_courses.student_id`와 슬롯 시간 조합을 빠르게 조회할 수 있도록 부모 키와 시간 기준 인덱스를 추가한다.

### 수동 커스텀 과목

`student_custom_courses`는 학생 소유의 시간표 전용 과목을 저장한다. 제목, 선택적 색상, 생성·수정 시각을 갖고 `student_id`는 `profiles.id`를 참조하며 `ON DELETE CASCADE`다.

`student_custom_course_schedule_slots`는 커스텀 과목의 복수 수업 시간을 저장한다. 컬럼과 시간 검증은 정규 과목 슬롯과 동일하고, `student_custom_course_id`는 `ON DELETE CASCADE`다.

두 슬롯 테이블은 학생이 자신의 행만 읽고 쓸 수 있는 RLS 정책을 둔다. 정규 과목 슬롯의 권한은 부모 `student_courses.student_id`의 소유권으로 검증한다. 커스텀 과목과 슬롯은 `student_custom_courses.student_id`의 소유권으로 검증한다.

## 정규 과목 추가·재동기화 흐름

1. 학생이 정규 과목을 추가하면 서버 액션이 학생 소유권과 과목 존재를 검증한다.
2. 같은 학생·과목·수강 상태의 `student_courses` 행을 찾거나 생성한다.
3. 현재 학기 기준으로 `course_schedules`를 먼저 조회한다. 슬롯이 있으면 모두 사용한다.
4. 강의계획서 슬롯이 없을 때만 `professor_teaching_slots`에서 같은 과목·학기의 슬롯을 조회해 사용한다. 숫자 요일은 UI가 쓰는 한국어 요일로 변환한다.
5. 두 원본 모두 비어 있으면 정규 과목용 다중 요일·시간 편집기를 표시한다. 이 경우에도 정규 과목 수강 행은 생성하고 슬롯 원본은 `manual`로 기록한다.
6. 신뢰할 수 있는 새 슬롯 집합이 결정되면 해당 `student_course_id`의 기존 슬롯을 트랜잭션에서 전부 교체한다. 따라서 기존에 잘못 저장된 단일 시간표 정보는 정답 슬롯으로 재등록된다.
7. 결과를 반환하고 `/mypage`, `/dashboard`, `/roadmap`, `/notices` 관련 데이터를 재검증한다.

기존 `student_courses`의 단일 `schedule_day`, `start_time`, `end_time`, `classroom` 값은 마이그레이션에서 `legacy` 슬롯으로 한 번 옮긴다. 이후 정규 과목이 재추가·재동기화되어 권위 있는 시간 데이터가 있으면 그 과목의 `legacy` 슬롯을 완전히 대체한다. 권위 있는 데이터가 없는 기존 수업은 기존 슬롯을 보존한다.

## 수동 과목 흐름

수동 과목 추가 화면은 제목을 입력하고, 요일 다중 선택으로 수업 회차를 추가한다. 각 회차는 요일, 시작·종료 시간, 강의실을 독립적으로 가진다. 최소 한 회차가 있어야 저장한다.

저장 시 `student_custom_courses`와 모든 슬롯을 함께 생성한다. 시간표 조회는 정규 과목 슬롯과 커스텀 슬롯을 하나의 표시 모델로 합친다. 커스텀 과목은 로드맵 드롭다운, 교수 공지 대상, 수강생 조인에서 제외한다.

## 로드맵·공지 연동

로드맵의 과목 드롭다운은 정규 과목의 `student_courses`만 조회한다. 시간 슬롯 수와 무관하게 정규 과목은 한 번만 보인다.

교수 공지 조회는 학생의 `student_courses.course_id` 목록으로 공지·게시물의 `course_id`를 조인한다. 정규 과목 추가 즉시 공지가 보이고, 삭제 즉시 대상 목록에서 빠진다. 별도 수강생 테이블을 중복 생성하지 않는다. `student_courses` 자체가 수강생 매핑의 기준이다.

## 삭제와 무결성

- 정규 시간표 과목 삭제: `student_courses`를 삭제한다. 관련 정규 슬롯은 외래 키로 삭제되고, 로드맵과 공지 쿼리는 더 이상 과목을 찾지 못한다.
- 수동 과목 삭제: `student_custom_courses`를 삭제한다. 관련 커스텀 슬롯만 삭제한다.
- 슬롯 단독 수정: 부모 과목·수강 관계는 유지한다.
- 시간 충돌은 저장을 막지 않는다. 충돌된 블록은 UI에서 부드러운 경고 상태로 표시한다. 대학 시간표는 중복 수강·보강 같은 예외가 있으므로 사용자가 최종 결정한다.

## API·서비스 경계

- `student-timetable` 서비스: 시간 원본 해석, 슬롯 검증, 정규 과목 동기화, 커스텀 과목 생성·삭제, 표시 모델 조립을 담당한다.
- 서버 액션: 인증된 학생을 확인하고 서비스 호출, 경로 재검증, UI용 성공·실패 결과만 반환한다.
- 조회 서비스: 마이페이지와 오늘 시간표 위젯이 공통 표시 모델을 사용하도록 하여 단일 요일 필드 의존성을 없앤다.
- 기존 로드맵·공지 서비스: `student_courses`를 기준으로 유지하되, 수강 상태가 시간표 등록 상태와 일치하도록 필터를 검토한다.

## 테스트와 검증

- 시간 원본 우선순위: 강의계획서 슬롯이 교수 슬롯보다 우선하는지 검증한다.
- 복수 회차: 월/수 또는 화/목 슬롯이 모두 저장·표시되는지 검증한다.
- 재동기화: 잘못된 기존 슬롯이 권위 있는 시간 슬롯으로 정확히 교체되는지 검증한다.
- 수동 정규 과목: 원본 데이터가 없을 때 복수 회차를 수동 저장하는지 검증한다.
- 커스텀 과목: 시간표에만 표시되고 로드맵·공지 목록에는 포함되지 않는지 검증한다.
- 삭제: 정규 과목 삭제가 슬롯, 로드맵 선택, 공지 수신을 함께 해제하는지 검증한다.
- RLS: 다른 학생이 정규·커스텀 시간표 데이터를 읽거나 변경할 수 없는지 검증한다.
