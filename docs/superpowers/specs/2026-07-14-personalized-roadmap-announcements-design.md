# 개인화 주차별 로드맵·공지·마이페이지 탭 설계

## 목표

교수의 승인된 1~15주차 강의 계획과 학생 온보딩 프로필을 결합해 학생별 학습 로드맵을 생성한다. 정형 구조와 검증은 규칙 기반으로 처리하고, 개인화 문장과 학습 활동만 OpenAI가 보강한다. 교수 메뉴 순서, 학생 공지 노출, 마이페이지 탭 필터도 같은 변경 범위에 포함한다.

## 범위와 경계

- 기존 `course_weekly_plans`는 교수 승인된 과목 기준 계획의 원본이다. 수정하거나 대체하지 않는다.
- 새 과목 개인화 설정은 분반(`course_offerings`) 기준으로 저장한다. 교수는 자신이 소유한 분반만 읽고 쓸 수 있다.
- 새 학생 로드맵 결과는 학생·분반·주차 기준으로 저장한다. 기존 `student_weekly_progress`는 진도/피드백 용도로 유지한다.
- 공지는 기존 `posts`의 `board_key = course_notice`와 알림 서비스만 재사용한다. 공지의 영속 구조를 중복 생성하지 않는다.
- API 키는 서버 전용 `OPENAI_API_KEY`만 사용하며 클라이언트 컴포넌트나 `NEXT_PUBLIC_*`에 노출하지 않는다.

## 데이터 모델

### `course_roadmap_personalization_sources`

분반별 교수 설정을 저장한다.

- `offering_id` (unique): 분반
- `professor_id`: 설정을 마지막으로 반영한 교수
- `foundation_knowledge`: 기초 지식 안내
- `focus_keywords`: 집중 키워드 JSON 배열
- `professor_notes`: 교수 수동 보완 메모
- `source_version`: 설정 반영 때마다 증가하는 양의 정수
- 생성/수정 시각

### `student_personalized_weekly_roadmaps`

학생별·분반별·주차별 최신 개인화 결과와 입력 버전을 저장한다.

- `student_id`, `offering_id`, `week_number` (unique)
- `baseline_title`, `baseline_topic`, `baseline_content`: 규칙 기반 원본 스냅샷
- `personalized_goal`, `learning_activities`, `review_guide`: AI 보강 결과
- `source_version`, `onboarding_hash`, `input_hash`: 재생성 판정값
- `generation_status`: `ready`, `fallback`, `failed`
- `generated_by_ai`, 생성/수정 시각

두 테이블 모두 RLS를 활성화한다. 학생은 자신에게 배정된 분반의 결과만 읽고, 교수는 자신이 소유한 분반의 설정만 변경할 수 있다. 서버 액션/서버 서비스도 세션과 소유권을 별도로 검증한다.

## 로드맵 생성 흐름

1. 교수 화면의 과목 선택은 소유한 분반의 승인된 `course_weekly_plans`와 개인화 설정을 병렬 조회해 폼을 초기화한다. 추천 사유 필드는 제거한다.
2. **학생 로드맵에 반영**은 설정을 Upsert하고 `source_version`을 증가시킨다. 기존 학생 결과는 삭제하지 않는다. 버전 불일치로 자연스럽게 오래된 결과가 된다.
3. 학생 로드맵 조회는 배정 여부를 확인한 뒤, 승인된 1~15주차를 주차 번호 순으로 정규화한다. 누락 주차는 명시적인 기본 문구로 채워 구조를 항상 15개로 만든다.
4. 학생 온보딩(학습 목표, 관심사, 약한 기초 등)과 교수 설정을 읽고 해시를 계산한다. 현재 결과의 `source_version`·`onboarding_hash`·`input_hash`가 모두 같으면 저장된 결과를 반환한다.
5. 불일치하거나 결과가 없으면 OpenAI Chat Completions에 정규화한 기준 계획과 학생 프로필을 전달한다. 모델은 주차별 목표, 활동 목록, 복습 가이드를 JSON으로만 반환한다.
6. 응답은 1~15주차 완전성, 중복, 문자열/배열 타입, 길이 제한을 검증한다. 개별 주차가 유효하지 않거나 API 키/네트워크/JSON 처리가 실패하면 해당 주차는 규칙 기반 기본값으로 저장한다. 이 경우 `generation_status = fallback`이며 학생 UI는 계속 정상 렌더링된다.
7. 검증된 결과를 Upsert하고 학생 주차별 로드맵 UI는 이 단일 타입만 소비한다.

LLM은 사실을 새로 만들지 않는다. 기준 계획에 없는 평가 일정·출석·성적·필수 과제를 생성하지 않도록 시스템 프롬프트에 명시한다. `gpt-4o-mini`, 낮은 temperature, 입력 길이 제한을 기본으로 사용한다.

## UI와 라우팅

### 교수

- 내 과목 로드맵 수정 폼: 과목 선택 프리로드, 기초 지식·집중 키워드·교수 메모, 반영 버튼과 처리 상태.
- 과목 관리 메뉴는 공통 정의에서 다음 순서를 사용한다: 내 과목 로드맵 수정 → 주간 계획 초안 검토 → 기존 중간 항목 → 기타 수업 설정.
- 웹 GNB, 교수 모바일 드로어/사이드바가 이 공통 정의를 소비한다.

### 학생 공지

- 공지 등록과 질문 요청 기반 공지 등록은 기존 서버 액션을 통해 `posts(course_notice)`에 저장하고, 수강생 알림을 발송한다.
- 대시보드의 확인할 알림 바로 아래에 공지 피드를 둔다. 공지 카드에는 닫기 버튼이 있으며, 사용자가 닫은 공지 ID는 버전이 있는 localStorage 키로 보관한다.
- 전체 공지 목록 페이지를 새 라우트로 추가한다. 학생 웹 GNB에 공지사항 링크를 넣고, 모바일 햄버거 메뉴의 과목 하위 항목에도 동일 경로를 넣는다.

### 학생 마이페이지

- 상단에 아이콘만 보이는 `전체`, `시간표`, `투두`, `커뮤니티` 탭을 둔다.
- 클라이언트 상태 `activeTab`으로 렌더링을 제어한다. 전체는 세 섹션을 모두, 개별 탭은 해당 섹션만 렌더링한다.
- 버튼과 신설 카드는 실선 테두리를 사용하지 않는다. 비활성은 투명/연한 회색 아이콘, 활성은 파스텔 배경과 `shadow-sm`를 사용한다.
- 시간표 셀은 `w-full`, 컴팩트 패딩, `break-all`, `line-clamp-2`, `truncate`를 유지해 모바일 가로 넘침을 막는다.

## 오류 처리와 재검증

- 서버 액션은 로그인, 역할, 교수-분반 소유권 및 입력값을 검증한다.
- OpenAI 실패는 사용자 오류로 전파하지 않고 규칙 기반 결과로 내려간다. 서버 로그에는 키나 개인 입력 원문을 기록하지 않는다.
- 설정 저장 후 해당 교수 화면, 학생 로드맵·대시보드·공지 경로를 재검증한다.
- 공지는 DB가 최신 원본이며, 닫기 상태는 UI 표시만 제어한다. 공지를 다시 열거나 다른 기기에서 보면 다시 보일 수 있다.

## 검증 계획

- 규칙 기반 15주차 정규화, LLM JSON 검증/폴백, 입력 해시·버전 재생성 판정을 단위 테스트한다.
- 교수 설정 Upsert/소유권, 학생 배정 검증, 공지 목록 필터를 서비스 테스트한다.
- 메뉴 순서, 추천 사유 제거, 공지 카드 닫기, 마이페이지 탭 필터, 모바일 시간표 오버플로 방지 조건을 컴포넌트 소스/행동 테스트한다.
- TypeScript 검사와 Next.js 프로덕션 빌드를 실행한다. 환경변수가 있는 경우 실제 OpenAI 호출은 작은 단일 테스트 요청으로만 확인하고, 값은 출력하지 않는다.
